# SparrowDB GUI 导入功能测试文件说明

## 测试文件概览

已为您创建了多个测试SQL文件，用于验证GUI界面的导入导出功能：

### 📁 单文件导入测试

#### 1. `test_import.sql` - 综合功能测试文件
**用途**: 测试GUI的基本导入功能
**内容**: 
- 创建5个相关联的表（学生、课程、选课、部门、教师）
- 插入约30+条测试数据
- 包含UPDATE、DELETE、SELECT等多种SQL语句
- 创建视图和索引（如果支持）

**测试步骤**:
1. 在GUI中选择 "文件" → "导入SQL文件..."
2. 选择 `test_import.sql`
3. 选择执行模式（建议先选择"是"容错模式）
4. 观察导入结果和状态反馈

**预期结果**:
- 成功创建5个表
- 插入数据后最终统计显示各表记录数
- 创建1个视图
- 所有操作完成后显示成功信息

#### 2. `test_error_handling.sql` - 容错模式测试文件
**用途**: 专门测试错误处理和容错模式
**内容**:
- 正常SQL语句与故意的错误语句混合
- 语法错误、重复主键、不存在的表等错误场景

**测试步骤**:
1. 选择 "文件" → "导入SQL文件..."
2. 选择 `test_error_handling.sql`
3. **重要**: 选择"是"（容错模式）
4. 观察哪些语句成功，哪些失败

**预期结果**:
- 容错模式：正确语句执行，错误语句跳过
- 最终test_table应包含部分记录
- 结果显示成功和失败的语句统计

### 📂 批量导入测试

#### 3. `test_batch_import/` 目录 - 批量导入测试
**用途**: 测试批量导入目录功能
**包含文件**:
- `01_init_schema.sql` - 创建表结构
- `02_insert_users.sql` - 插入用户数据  
- `03_insert_products.sql` - 插入产品数据
- `04_insert_orders.sql` - 插入订单数据
- `05_final_report.sql` - 生成统计报告

**测试步骤**:
1. 选择 "文件" → "批量导入目录..."
2. 选择 `test_batch_import` 目录
3. 文件模式保持默认 `*.sql`
4. 选择执行模式
5. 开始批量导入

**预期结果**:
- 按文件名顺序执行（01→02→03→04→05）
- 创建用户、产品、订单三个业务表
- 最终显示完整的统计报告
- 验证数据完整性

## 🧪 推荐测试流程

### 第一轮：基础功能测试
1. **简单导入**: 使用 `test_import.sql` 测试基本导入功能
2. **查看结果**: 在GUI的结果区域查看执行详情
3. **验证数据**: 使用查询功能验证导入的数据

### 第二轮：容错能力测试  
1. **错误处理**: 使用 `test_error_handling.sql` 测试容错模式
2. **模式对比**: 分别用容错模式和快速失败模式测试
3. **结果分析**: 比较两种模式的执行结果差异

### 第三轮：批量处理测试
1. **批量导入**: 使用 `test_batch_import/` 目录测试
2. **进度监控**: 观察批量处理的进度显示
3. **结果汇总**: 查看最终的统计报告

### 第四轮：导出功能测试
1. **导出验证**: 导出刚才导入的数据库
2. **单表导出**: 选择某个表单独导出
3. **文件比较**: 比较导出文件与原始文件的差异

## 📊 测试数据说明

### test_import.sql 包含的表结构:
- **students**: 学生信息（id, name, age, grade, email）
- **courses**: 课程信息（course_id, course_name, credits, instructor）
- **enrollments**: 选课信息（student_id, course_id, enrollment_date, score）
- **departments**: 部门信息（dept_id, dept_name, location, budget）
- **teachers**: 教师信息（teacher_id, teacher_name, dept_id, title, salary）

### 批量导入测试的表结构:
- **users**: 用户信息（user_id, username, email, created_date）
- **products**: 产品信息（product_id, product_name, price, category）
- **orders**: 订单信息（order_id, user_id, order_date, total_amount）

## ⚠️ 测试注意事项

1. **数据库状态**: 每次测试前建议清空数据库或使用新的数据库
2. **编码问题**: 确保SQL文件以UTF-8编码保存
3. **权限检查**: 确保有读取测试文件的权限
4. **错误日志**: 仔细查看错误信息，有助于发现问题
5. **性能观察**: 注意导入大文件时的性能表现

## 🔍 故障排除

### 如果导入失败：
1. 检查SQL语法是否正确
2. 确认表是否已存在（可能需要先删除）
3. 查看错误消息获取具体原因
4. 尝试使用容错模式

### 如果批量导入失败：
1. 检查目录路径是否正确
2. 确认文件模式匹配是否正确
3. 验证文件权限
4. 逐个文件测试找出问题文件

### 如果性能过慢：
1. 检查数据量大小
2. 考虑分批处理
3. 查看系统资源使用情况

- ✅ 结果反馈清晰准确
- ✅ 导入的数据能正确查询
- ✅ 性能表现合理
