# 分片功能快速入门指南

## 🚀 5分钟快速体验

### 步骤1: 启动GUI
```bash
# 在SqlTranslater/DB目录下运行
.\run_gui.bat
```

### 步骤2: 创建测试数据
在SQL输入框中执行以下命令：
```sql
-- 创建测试表
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(50),

    age INT

INSERT INTO users VALUES (7, '周九', 'zhoujiu@email.com', 31);
INSERT INTO users VALUES (8, '吴十', 'wushi@email.com', 27);
```

### 步骤3: 创建分片
点击"分片管理"按钮，在分片管理器中：
1. 选择表：`users`
2. 分片键：`id`
3. 策略：`HASH`
4. 分片数：`4`
5. 点击"创建分片"

### 步骤4: 查看分片效果
在分片管理器中点击"统计信息"查看分片统计，或执行：
```sql
SHOW SHARDS users;
SHARD STATS users;
```

### 步骤5: 测试分片查询
```sql
-- 这些查询会自动路由到相应的分片
SELECT * FROM users WHERE id = 1;
SELECT * FROM users WHERE id = 5;
```

## 💡 为什么需要分片？

### 1. **性能瓶颈**
```
单表数据量增长 → 查询变慢 → 用户体验下降
```

### 2. **扩展性限制**
```
单机硬件限制 → 无法处理更大数据量 → 业务发展受限
```

### 3. **成本问题**
```
高端服务器成本高 → 资源利用率低 → 投资回报率低
```

### 4. **可靠性风险**
```
单点故障 → 整个系统不可用 → 业务损失
```

## 🎯 最佳实践建议

### 1. 分片键选择
- ✅ 选择高基数字段（如用户ID、订单ID）
- ✅ 选择查询频繁的字段
- ❌ 避免低基数字段（如性别、状态）
- ❌ 避免经常变化的字段

### 2. 分片数量规划
- 小表（<100万）：2-4个分片
- 中表（100万-1000万）：4-8个分片
- 大表（>1000万）：8-16个分片

### 3. 分片策略选择
- **哈希分片**：数据均匀分布，适合随机查询
- **范围分片**：适合范围查询，但可能产生热点

### 4. 监控指标
- 分片负载均衡情况
- 查询响应时间
- 分片存储使用率
- 热点分片识别

## 🚨 注意事项

### 1. 查询限制
- 分片后某些查询可能需要扫描所有分片
- 建议优化查询模式，尽量使用分片键查询

### 2. 事务处理
- 跨分片事务处理复杂
- 建议在应用层处理跨分片事务

### 3. 数据迁移
- 分片后数据迁移需要重新规划
- 建议在业务低峰期进行分片操作

### 4. 监控维护
- 需要监控各分片的状态
- 定期检查分片负载均衡情况
